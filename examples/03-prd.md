# 예시 3. 기획 문서 (PRD)

재현 예시입니다. 실사용 기록인 예시 1, 2와 달리 이 문서는 적용 범위를 보이려고 새로
만들었습니다. 원문은 LLM 이 기획 문서를 쓸 때 흔히 내놓는 형태를 재현한 것입니다.

## 원문

```markdown
# 알림 센터 PRD

## 배경

유저가 중요한 변경을 놓치는 케이스가 늘어나고 있음. 현재는 이메일로만 전달 —
열람률이 낮다. 인앱 알림 센터를 붙여 도달률을 끌어올린다.

## 목표

- **도달률 개선.** 이메일 대비 3배.
- 알림의 우선순위의 구분이 가능해야 함
- 읽음/안읽음 상태 관리
- 유저별 알림 설정 → 카테고리 단위로 온오프

## 범위

인앱 알림 센터 · 알림 설정 화면 · 배지 카운트. 푸시는 이번 스코프 아님.

## 리스크

알림이 너무 많으면 유저가 다 꺼버린다 — 이러면 도달률이 오히려 떨어진다.
초기에는 보수적으로 세팅.
```

## 개선본

```markdown
# 알림 센터 PRD

## 배경

사용자가 중요한 변경을 놓치는 경우가 늘고 있습니다. 현재는 이메일로만 전달하는데
열람률이 낮습니다. 인앱 알림 센터를 도입해 도달률을 높입니다.

## 목표

- 도달률을 이메일 대비 3배로 개선합니다.
- 알림 우선순위를 구분할 수 있어야 합니다.
- 읽음 여부를 상태로 관리합니다.
- 사용자가 카테고리 단위로 알림을 켜고 끌 수 있어야 합니다.

## 범위

인앱 알림 센터, 알림 설정 화면, 배지 카운트를 포함합니다. 푸시 알림은 이번 범위에
넣지 않습니다.

## 위험 요인

알림이 지나치게 많으면 사용자가 전부 꺼 버립니다. 그러면 도달률이 오히려 떨어지기
때문에, 초기에는 보수적인 기본값으로 설정합니다.
```

## 무엇이 바뀌었나

| 규칙 | 원문 | 개선본 |
| --- | --- | --- |
| 비ASCII 문장부호 | `이메일로만 전달 — 열람률이 낮다` | `이메일로만 전달하는데 열람률이 낮습니다` |
| 비ASCII 문장부호 | `알림 센터 · 알림 설정 화면 · 배지 카운트` | `알림 센터, 알림 설정 화면, 배지 카운트` |
| 비ASCII 문장부호 | `알림 설정 → 카테고리 단위로 온오프` | `카테고리 단위로 알림을 켜고 끌 수 있어야` |
| `~의` 남용 | `알림의 우선순위의 구분이 가능해야 함` | `알림 우선순위를 구분할 수 있어야 합니다` |
| 종결어미 완성 | `늘어나고 있음`, `읽음/안읽음 상태 관리` | `늘고 있습니다`, `읽음 여부를 상태로 관리합니다` |
| 비유적 어휘 | `도달률을 끌어올린다` | `도달률을 높입니다` |
| 섹션 제목 | `리스크` | `위험 요인` |
| 음차 어휘 | `유저`, `케이스`, `스코프`, `세팅` | `사용자`, `경우`, `범위`, `설정` |
| 접속 표시어 | `다 꺼버린다. 이러면 도달률이 떨어진다.` | `전부 꺼 버립니다. 그러면 ... 떨어지기 **때문에**` |

`유저`, `케이스`, `스코프` 를 우리말로 옮긴 것은 기술 용어 규칙과 반대로 보이지만
그렇지 않습니다. 이들은 설정 키나 API 이름이 아니라 일반 명사를 음차한 것뿐이고,
`사용자`, `경우`, `범위` 라는 정착된 번역어가 이미 있습니다. 반대로 `배지 카운트` 나
`인앱` 은 그대로 두었습니다.
